# Android 会话布局优化方案

## 目标

会话正文是手机屏幕的首要内容。输入区和一级导航必须保持可操作性，同时把固定占用控制在必要范围内，避免大面积留白挤压历史消息。优化先覆盖窄屏手机，600dp 以上继续使用现有 Rail 和双栏断点。

## 布局合同

|区域|当前问题|目标尺寸|实现约束|
|---|---|---|---|
|一级底部导航|Material 默认栏高和系统 inset 叠加后过高|内容栏 64dp，另加真实 navigation inset|每个入口保留至少 48dp 触控区域；图标 20dp；标签不超过一行|
|消息输入行|OutlinedTextField 默认最小高度偏大|单行空草稿 48dp；多行随内容增长，最多 120dp|附件、模式、发送操作仍可用；键盘只由 ChatScreen 消费 IME inset|
|会话正文|被底部固定区域挤压|LazyColumn 使用剩余空间，底部只保留 8dp 呼吸间距|历史阅读不因尺寸变化抢回滚动位置|
|会话标题|与正文层级不够明确|标题 16sp/22sp，辅助状态 12sp/16sp|长标题省略，不增加固定高度|

## 字号层级

- 正文：16sp/24sp，保持长文本阅读密度。
- 会话标题：16sp/22sp；页面标题：20sp/26sp。
- 输入内容和主要按钮：15sp/20sp。
- 导航标签、状态、附件名：11–12sp/16sp。
- 代码、工具输出和诊断细节：13sp/19sp，使用等宽字体或 `bodySmall`。

字号通过 Material `Typography` 和组件局部 style 明确指定，不能用一个全局字号覆盖所有组件。支持系统大字号时不得固定裁切文字。

## 交互与 Insets

底部导航只消费 `navigationBars`，输入区只消费 IME；键盘打开时隐藏窄屏一级导航。输入区不再额外叠加 `imePadding`，避免键盘上方出现重复空隙。导航和输入的视觉高度可以压缩，但触控目标不得低于 48dp。

## 验收

在窄屏竖屏、横屏、键盘展开、深浅主题和 100%/200% 字号下检查：

1. 底部导航内容栏为 64dp 左右，系统手势区只保留真实 inset。
2. 空输入行约 48dp；输入多行时最多 120dp，正文仍有可滚动剩余空间。
3. 发送、停止、附件和导航入口的触控区域至少 48dp。
4. 键盘不遮挡输入，历史上翻时新消息不抢滚动。
5. 正文、标题、状态和导航标签具有可辨识的字号层级。

验证命令：`gradlew.bat :app:testDebugUnitTest`、`gradlew.bat :app:assembleDebug`；有设备时追加 `:app:connectedDebugAndroidTest` 并保留会话布局截图。
