# 会话、编辑重跑与执行队列整改规范

> 文档状态：实施前基线。适用于 Core、Server、Web、Android 和协议层。
> 本文先定义行为和验收标准，再允许修改实现。旧数据按一次性迁移转换到本文定义的关系模型，不保留双重解释。

## 1. 目标

会话历史必须能回答三个问题：当前用户正在看的哪条对话路径、某条消息被哪次编辑替代、某个运行当前是否仍属于队列。编辑重跑、审查、改进、取消、抢占、排序和页面切换都只能改变自己的对象，不能通过迟到回执覆盖另一条会话路径。

Core 是唯一事实源。客户端只保存可重建投影和未提交草稿，不自行推断分支、队列位置或运行归属。

## 2. 术语和关系

- **会话 session**：账号下的长期容器。
- **对话路径 branch**：同一会话中的一条可见消息链。每个会话始终有一个主分支；编辑会创建新的替代路径并原子切换为活动路径。
- **消息 message**：不可变的用户、助手或工具记录。编辑不会修改已完成消息的正文。
- **编辑替代 edit replacement**：`replacementMessageId` 指向新用户消息，`replacesMessageId` 指向被编辑的旧用户消息；替代消息继承旧消息的父消息，不继承旧消息之后的后代。
- **运行 run**：一次排队、执行或质量操作。Agent 运行有用户消息；审查/改进运行有目标助手消息，但不会自动成为新的对话分支。
- **队列 entry**：一个尚未完成的运行及其稳定的 `queueOrder`。位置是投影值，不能作为身份。

关系必须满足：

1. 一个消息只能有一个直接父消息；父消息必须在同一会话且序列更早。
2. 活动分支只能沿父链从头到尾读取；不得用“全局序列早于某条消息”代替父链可见性。
3. 被编辑消息及其旧后代保留在数据库和审计中，但从活动分支隐藏；历史接口必须明确返回当前路径，不把隐藏旧路径混入普通历史。
4. 质量结果是目标消息的派生记录。审查不改写、不替代目标；改进生成新助手消息，默认以目标为父消息，但只有用户明确“采用改进结果”时才创建新的对话替代路径。
5. 分支切换、消息写入和活动路径更新必须在同一数据库事务中完成，并按一个事件批次发布。

## 3. 编辑与重跑行为

### 3.1 已完成用户消息

编辑已完成用户消息必须执行以下原子操作：

1. 校验消息属于当前会话、角色为 user、状态为 complete，且目标消息在当前活动路径。
2. 若当前会话有其他 queued/preflight/running/verifying 的 Agent 运行，拒绝编辑并返回可行动原因；质量运行不阻止编辑，但不得被编辑后的路径误收录。
3. 建立新的替代路径，记录 `replacesMessageId`、`forkParentMessageId` 和 `sourceBranchId`。
4. 新用户消息使用被编辑消息的直接父消息作为 `parentMessageId`；根消息编辑时父消息为空。
5. 活动分支切换到新路径，创建新的 Agent Run；旧消息、旧助手回复及旧工具记录保持可审计，但不出现在新路径普通历史中。
6. 返回新 Run 和新消息 ID。客户端只能把该回执合并到发起时的会话/分支版本。

### 3.2 排队中的用户消息

排队中的消息可以原地改正文，只允许更新同一个 Run 和同一个 messageId，不创建新分支、不追加第二个 Run。若该 Run 已进入 preflight 或更晚阶段，编辑必须改走“取消并重新发送”确认流程，不能静默改变模型已经读取的输入。

### 3.3 重跑

“重跑”是对指定用户消息创建一个新的 Agent Run。它与编辑相同地替代旧消息之后的路径，但保留原用户正文；重跑结果完成后，旧结果在当前路径中被新结果覆盖。普通会话历史只显示新路径中的一份用户消息和一份当前结果，不同时显示被重跑的旧结果。

## 4. 审查与改进

- 审查只读目标助手消息，结果进入质量记录和质量面板，不插入普通会话正文。
- 改进默认生成一个派生助手结果，结果卡片显示“基于哪条答案改进”。它不自动替换当前会话路径，避免用户点击一次改进就改变后续上下文。
- 用户选择“采用改进结果”时，Core 创建明确的替代路径或替代结果事件；未采用的改进结果只能在质量详情中查看。
- 同一目标、同一操作类型只能有一个活动质量 Run；重复请求返回原 Run。
- 质量 Run 必须绑定 `sessionId`、`targetMessageId`、发起时的 `branchRevision`。目标已不在当前路径时，结果仍可完成，但不得自动写入当前路径。
- 取消、失败和超时不会产生助手正文；结果未知时显示“需要核实”，禁止自动再次调用模型。

## 5. 队列和抢占

### 5.1 状态

Agent/command/quality Run 使用统一状态：`queued → preflight → running/verifying → completed|failed|cancelled|interrupted`。`awaiting_input` 和 `awaiting_confirmation` 是运行中的暂停状态，不应被普通队列排序跳过。

### 5.2 queue 模式

同一会话同一时间最多一个执行 Run；新消息进入队尾。跨会话并发由全局 semaphore 控制。拖拽、上移、下移和置顶只改变 queued 项，必须提交完整的版本号/Run ID 集合，服务端检测冲突后拒绝过期排序。

### 5.3 preemptive 模式

新 Agent 消息到达时：

1. 取消该会话所有尚未开始的 queued Run，并标记原因为 superseded；不删除消息和审计记录。
2. 请求当前运行停止。已完成的只读动作可重放；副作用动作进入 uncertain，必须等待用户核实，禁止自动重放。
3. 新 Run 仍从新消息创建，不能复用旧 Run ID 或旧响应。
4. 旧 Run 的迟到事件只能更新旧 Run；客户端不得把它们投影到新 Run 或新活动分支。

抢占不是强制杀死进程。停止响应、未知副作用和恢复决策必须在 Run 面板中可见。

### 5.4 队列操作

编辑排队项只更新原 Run；取消只取消选中项；置顶/排序不影响正在运行项；页面切换、后台恢复和重连都从服务端快照重建队列。任何成功提示都必须以服务端回执为准。

## 6. 客户端投影与迟到回执

每个会话投影携带 `sessionRevision`、`branchRevision` 和 `queueRevision`。写请求记录发起时三者；回执只有在账号、会话、分支和对象 ID 全部匹配时才能修改当前视图。收到更高版本快照时丢弃本地旧排序和旧分页游标，重新读取当前路径。

历史分页按 `branchRevision` 固定视图读取。上翻过程中发生编辑或分支切换，保留旧页作为“旧路径”临时阅读，但返回当前会话时必须重新定位活动路径末尾，不能把两条路径拼接。

## 7. 一次性迁移

迁移把现有 `conversation_branch_forks`、父消息和活动分支转换为明确的替代关系：

- 为每次历史编辑生成稳定的 replacement 关系和源分支 ID。
- 根据替代消息的直接父消息确定公共前缀；无法唯一确定时标记为 `needs_review`，迁移失败并保留备份，不猜测路径。
- 将已有质量结果绑定目标消息和当时分支版本；不把历史改进结果自动并入正文。
- 为所有 queued Run 重新计算连续 queueOrder；终态 Run 的 queueOrder 清空。
- 迁移完成后 schema 版本递增，旧读取逻辑删除，不保留兼容分支。

## 8. 验收矩阵

至少覆盖以下场景，Web 和 Android 各执行一次，Core 单测覆盖事务和并发：

1. 根消息编辑、末尾消息编辑、中间消息编辑、连续两次编辑。
2. 编辑后分页、刷新、断线重连、切换会话和返回旧路径。
3. 重跑只保留新结果；旧结果仍可在审计/旧路径查看。
4. 审查不污染正文；改进未采用不改变当前上下文；采用改进生成明确替代关系。
5. queue 模式多条消息、队列编辑、排序冲突、取消单项、取消后继续执行。
6. preemptive 模式抢占 queued、running、只读动作和副作用动作；迟到事件隔离。
7. 账号切换、删除会话、后台恢复、重复点击、网络超时和结果未知。

任何一个场景失败，都不能发布客户端或服务端版本。
