# UmaAgent 后端设计

## 契约与数据

Core 是用户、会话、运行、权限和事件的事实源。客户端保存可重建的展示缓存，以及尚未提交的本机草稿；草稿不充当服务端业务事实。当前契约为 Protocol v16、HTTP `/api/v16`、业务 schema 27；服务不提供旧路由、双写或旧格式解析。schema 26 数据通过停服后显式执行的一次性升级工具转换，转换前生成独立备份，失败保持原库可恢复。

会话编辑、重跑、审查、改进和队列行为以[会话、编辑重跑与执行队列整改规范](conversation-execution-recovery-design.zh-CN.md)为准。消息正文不可变；编辑通过明确的替代关系和活动分支切换隐藏旧后代。历史读取按父链计算可见路径，不能用全局 sequence 截断代替父链。质量结果默认是派生记录，不自动污染普通正文。

用户记录的 `auto_approve` 默认开启。`GET/PATCH /api/v16/account/execution-settings` 仅操作认证账号，字段为 `autoApprove: boolean`。客户端不能提交其他用户 ID。设置事务提交后，开启策略会解决该用户已有待审批，计划确认亦进入执行。关闭策略只影响后续审批点，不中断已获许可的工具。账号权限、工作区、SSRF、工具可见性及未知副作用恢复不受该开关影响。

## 执行与同步

HTTP 接受请求后创建唯一 Run；消息 ID 与 Action Ledger 保证去重，单会话队列与跨会话并发分别控制。队列排序只作用于 queued 项，抢占会取消未开始项并把运行中的未知副作用标记为 uncertain。Agent、直接命令和调度使用同一个审批服务，不由客户端模拟点击批准。未决副作用不自动重放。

持久事件拥有递增游标；临时 `message.delta` 的 sequence 为 0，只用于显示，不推进持久游标。客户端按事件投影更新会话，缺口补拉，连接恢复时通过快照校准。终态内容覆盖临时增量。账号切换使旧连接、请求和缓存失效。

预检后的路由、检查点和运行状态在同一个 EventHub 事务提交，提交后才按顺序发布事件；最终假设说明与完成事件也在同一事务内。事务不跨模型请求或工具执行，避免持锁等待网络。Run 局部更新用静态 SQL：undefined 保留原值，null 清空可空字段，空数组、空字符串和 0 均是有效更新，不能用真假值判断丢弃。

工具的静态 TypeBox schema 在模块级复用，执行闭包仍绑定当前会话及账号；上下文容量校验返回已计算的 token 数供模型调用记录使用，不重复估算或裁剪输入。

Embedding 并发许可在释放时直接交给队首等待者，交接不增加占用计数，避免多轮请求后许可泄漏。启用但缺少密钥在获取数据库锁和创建遥测 Worker 前失败；批量请求校验向量数量、索引、有限数值和维度，失败向知识索引状态传播；认证及响应合同错误立即失败，仅网络异常和明确瞬态 HTTP 状态参与有限重试。仅显式禁用 Embedding 时使用纯关键词检索，不以吞掉供应商错误伪装索引成功。

## 模块边界

Protocol 提供严格类型，Client 负责通信，Server 负责认证和传输，Core 负责业务编排，Repository 负责事务内读写。账号策略、审批、命令、调度、恢复保持独立职责；运行门面只组合这些能力。前端状态不成为业务状态机的新分支。

允许的Web来源按精确Origin配置；跨域预检包含当前接口实际使用的GET、HEAD、POST、PUT、PATCH、DELETE和OPTIONS，以及Authorization、Content-Type、Traceparent。Profile的PUT必须经过同一预检规则，不能只验证同源页面。

## 可观测性

模型审计的 totalTokens、inputTokens 等明确数值计数保留；同名字符串、访问令牌及嵌套凭据仍脱敏。运营和诊断汇总读取持久化计数，不能把脱敏占位转成 NaN 或 null 后伪装为无用量。

现有 W3C trace context 串联 HTTP、队列、Run、预检、模型、工具、审批及 Worker。单调时钟计算本进程耗时，不跨设备相减。诊断数据与业务库分离，按用户所属 Run 过滤后分页。禁止记录完整提示词、正文、工具参数和秘密。

遥测写入交给独立 Worker，以有界队列和批量事务避免 SQLite 锁等待阻塞业务线程。查询、flush、关闭和失败计数具有明确协议；取消、异常、超时及退出均终结 Span。客户端通过 Run/Trace ID 打开阶段详情。主 Agent 模型失败记录 ModelError 与脱敏后的原因，避免只有 error 状态而无可诊断信息。辅助模型调用在业务库创建或结算失败时也终结 Span，结算不重复写入；模型与结算同时失败保留两个错误。

错误字符串中的敏感对象、数组、换行及截断值从敏感值起点脱敏至末尾，避免嵌套尾部泄露；保留前面的错误分类。已脱敏占位不参与二次吞并。脱敏不能作为记录完整提示词或工具参数的理由。

## 验收与运行

性能预算以 `scripts/perf-baseline.json` 为准，不以关闭功能、强制 GC 或降低测量负载通过。固定基准三轮比较，四小时正常模式 Faux soak；真实模型使用独立 state/workspace/telemetry。最终结果只写发布验收文档，设计规格不冒充测试证明。
