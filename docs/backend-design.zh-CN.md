# UmaAgent 后端设计

## 契约与数据

Core 是用户、会话、运行、权限和事件的事实源。客户端保存可重建的展示缓存，以及尚未提交的本机草稿；草稿不充当服务端业务事实。当前契约为 Protocol v16、HTTP `/api/v16`、业务 schema 27；服务不提供旧路由、双写或旧格式解析。服务不提供迁移工具；历史数据库和备份必须保留在原版本隔离环境中，当前服务拒绝旧 schema。

当前发布配置将 `default`、`reasoning`、`fast` 和 `vision` 四个角色统一解析为 `openai/gpt-6.1-sol`。创建 session 时记录该模型引用；批量切换已有 session 只更新 session 的当前模型字段，历史 Run 的模型快照保持不可变。

会话编辑、重跑和队列行为以[会话、编辑重跑与执行队列整改规范](conversation-execution-recovery-design.zh-CN.md)为准。消息正文不可变；编辑通过明确的替代关系和活动分支切换隐藏旧后代。历史读取按父链计算可见路径，不能用全局 sequence 截断代替父链。

用户记录的 `auto_approve` 默认开启。`GET/PATCH /api/v16/account/execution-settings` 仅操作认证账号，字段为 `autoApprove: boolean`。客户端不能提交其他用户 ID。设置事务提交后，开启策略会解决该用户已有待审批，计划确认亦进入执行。关闭策略只影响后续审批点，不中断已获许可的工具。账号权限、工作区、SSRF、工具可见性及未知副作用恢复不受该开关影响。

## 执行与同步

单次模型 Provider 请求及其重试由 `runtime.modelTimeoutMs` 设置墙钟上限，默认 600000 毫秒（10 分钟）；该上限不包含进入 Run 前的队列等待，多轮 Agent 每轮请求分别计时。应用层在尚未向用户暴露有效输出前，对可恢复的 Provider 中断最多额外重试 7 次，使用带抖动的指数退避（1 秒起、30 秒封顶）；缺失流结束标记最多重试 5 次。SDK HTTP 状态重试仍最多 5 次，保留最长 120 秒的 `Retry-After` 预算；两层重试共用单次请求总时限。到期会终止当前 Provider 请求，用户取消使用独立信号即时中断。已有配置若显式设定更短时限仍以配置为准。部分流输出后不自动重放，避免重复文本或未知副作用。超时仍应通过 Model Trace 的耗时、重试事件和错误状态定位，不以无限延长等待掩盖供应商故障。

HTTP 接受请求后创建唯一 Run；消息 ID 与 Action Ledger 保证去重，单会话队列与跨会话并发分别控制。队列排序只作用于 queued 项，抢占会取消未开始项并把运行中的未知副作用标记为 uncertain。Agent、直接命令和调度使用同一个审批服务，不由客户端模拟点击批准。未决副作用不自动重放。

持久事件拥有递增游标；临时 `message.delta` 的 sequence 为 0，只用于显示，不推进持久游标。客户端按事件投影更新会话，缺口补拉，连接恢复时通过快照校准。终态内容覆盖临时增量。账号切换使旧连接、请求和缓存失效。

预检后的路由、检查点和运行状态在同一个 EventHub 事务提交，提交后才按顺序发布事件；最终假设说明与完成事件也在同一事务内。事务不跨模型请求或工具执行，避免持锁等待网络。Run 局部更新用静态 SQL：undefined 保留原值，null 清空可空字段，空数组、空字符串和 0 均是有效更新，不能用真假值判断丢弃。

工具的静态 TypeBox schema 在模块级复用，执行闭包仍绑定当前会话及账号；上下文容量校验返回已计算的 token 数供模型调用记录使用，不重复估算或裁剪输入。

Embedding 并发许可在释放时直接交给队首等待者，交接不增加占用计数，避免多轮请求后许可泄漏。启用但缺少密钥在获取数据库锁和创建遥测 Worker 前失败；批量请求校验向量数量、索引、有限数值和维度，失败向知识索引状态传播；认证及响应合同错误立即失败，仅网络异常和明确瞬态 HTTP 状态参与有限重试。仅显式禁用 Embedding 时使用纯关键词检索，不以吞掉供应商错误伪装索引成功。

## 模块边界

Protocol 提供严格类型，Client 负责通信，Server 负责认证和传输，Core 负责业务编排，Repository 负责事务内读写。账号策略、审批、命令、调度、恢复保持独立职责；运行门面只组合这些能力。前端状态不成为业务状态机的新分支。

允许的Web来源按精确Origin配置；跨域预检包含当前接口实际使用的GET、HEAD、POST、PUT、PATCH、DELETE和OPTIONS，以及Authorization、Content-Type、Traceparent。Profile的PUT必须经过同一预检规则，不能只验证同源页面。

## 可观测性

模型审计的 totalTokens、inputTokens 等明确数值计数保留；同名字符串、访问令牌及嵌套凭据仍脱敏。运营和诊断汇总读取持久化计数，不能把脱敏占位转成 NaN 或 null 后伪装为无用量。

现有 W3C trace context 串联 HTTP、WebSocket、队列、Run、预检、模型、工具、审批及 Worker。单调时钟计算本进程耗时，不跨设备相减。外部 `traceparent` 的父 Span ID 用于跨服务关联，不要求该父级存在于本地库；入口 Span 通过 `trace.parent_remote` 明确标记这一来源，本地派生 Span 显式标记为 false。孤儿统计排除此类远端根，同时继续报告缺失的本地父 Span。对旧遥测行不做批量回写；历史 `server.http` 入口按其入口语义识别远端父级。诊断数据与业务库分离，按用户所属 Run 过滤后分页。禁止记录完整提示词、正文、工具参数和秘密。

Trace 查询支持 `runId`、`traceId`、时间范围、状态、名称、`service`、`kind`、`offset` 和 `limit`；普通账号必须先通过自己拥有的 Run，管理员也必须使用至少一个过滤条件。服务端先完成权限和 Run 子树过滤，再分页并计算祖先深度；分页树根是本地链路的最上层 Span，外部父级不作为本地孤儿节点。Span 的 `active` 状态不会通过查询接口返回；服务重启会将遗留 Span 终结为 `IncompleteSpan`。WebSocket 握手 HTTP Span 在升级后立即结束；连接 Span 在正常关闭（1000）、服务关闭（1001）、异常关闭、错误和服务清理时分别记录 ok、cancelled 或 error，并清除订阅和认证定时器。Preflight Provider 失败或取消时也显式结束阶段 Span，不把预期失败留作父 Span 结束时的 `IncompleteSpan`。`queue.wait`、模型重试、工具超时、审批等待、取消和 Worker 断连都必须有可查询的阶段 Span 或事件。

遥测写入失败只增加失败计数，不回滚业务事务；批量队列包含排队和在途上限，`flush` 是读取前的持久化屏障，关闭会先排空并终止 Worker。资源报告同时记录 CPU、RSS、堆、事件循环延迟、WAL、活动 Run 和排队 Run，用于将长尾请求与资源峰值关联。CPU 平均按采样时长加权，延迟 p95 使用 nearest-rank，峰值使用窗口内最大样本；汇总由 SQLite 完成，不把时间窗内全部资源行复制到 Node 堆。遥测维护在 SQLite 内聚合过期 Span 后删除明细，避免把历史链路一次性加载到 Node 堆。

遥测写入交给独立 Worker，以有界队列和批量事务避免 SQLite 锁等待阻塞业务线程。查询、flush、关闭和失败计数具有明确协议；取消、异常、超时及退出均终结 Span。客户端通过 Run/Trace ID 打开阶段详情。主 Agent 模型失败记录 ModelError 与脱敏后的原因，避免只有 error 状态而无可诊断信息。辅助模型调用在业务库创建或结算失败时也终结 Span，结算不重复写入；模型与结算同时失败保留两个错误。

错误字符串中的敏感对象、数组、换行及截断值从敏感值起点脱敏至末尾，避免嵌套尾部泄露；保留前面的错误分类。已脱敏占位不参与二次吞并。脱敏不能作为记录完整提示词或工具参数的理由。

## 验收与运行

性能预算以 `scripts/perf-baseline.json` 为准，不以关闭功能、强制 GC 或降低测量负载通过。固定基准三轮比较，四小时正常模式 Faux soak；真实模型使用独立 state/workspace/telemetry。最终结果只写发布验收文档，设计规格不冒充测试证明。

## 本轮强化约束（2026-10-23）

- 遥测脱敏必须完整遮蔽 Authorization 的 Basic/Bearer 等认证值以及多段 Cookie，不能只去掉认证方案名或首个 cookie。保留错误分类，不保存秘密尾部。
- 8192 条写入上限也约束尚在构建中的逻辑事务。超大事务整组丢弃并精确计数，不能先分配无限数组再检查；异常事务不影响同批其他记录。
- Web 的持久投影只接受比当前快照游标更新的事件，迟到的旧事件不能把完成状态退回执行中。重复/空白以外的实际增量保持逐字保真；重复或缺口增量不应创建无变化投影。
- 本轮不改变协议、业务或遥测 schema，不迁移、不删除历史用户数据；测试仅使用独立 Faux 数据。现有错误记录仅作只读脱敏聚合，不能由失败摘要推断原始网络根因。

验收隔离：Faux 的 state、workspace、skills 均归本次独立目录；检测到既有 state.db 即在业务库/遥测创建前拒绝启动。不得把测试工作区指向源码根目录或删除调用者的既有数据库。

依赖安全：正文清洗、HTTP/MCP 与文档解析只使用当前已修复版本；依赖锁必须通过官方 npm advisory 检查。officeparser 8 的 Worker 仍关闭 OCR、原始内容和嵌套附件提取，保持只输出文档文本的边界。

## 网页抓取的网络边界

`safeFetch` 使用 `ipaddr.js` 解析地址，只允许公网单播。IPv6 URL 的方括号先移除，字面 IP 直接分类；域名解析得到的每个地址都须通过相同校验，并将选定结果绑定到本次连接，防止解析与连接之间更换地址。IPv4 映射 IPv6 先还原再分类；每次重定向重新执行边界校验。DNS错误与网络策略拒绝分别报告，不把私网目标误报为DNS故障。
